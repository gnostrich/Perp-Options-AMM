## 1. What the protocol IS (the operator's plain English, his own terms — entries 44/71/81)
A reply or question that reaches the operator must be one he can read ONCE, with no scrollback and
no internal vocabulary, and act on. Concretely, the operator's own requirements:
- **Plain English; no agent-coined or internal jargon unglossed.** (entries 44, 99)
- **Technical content = a TABLE comparing the existing thing with what you plan to do, + the core
  formula(s), + the literal edit shown.** (entries 71, 81: "a single core formula table and
  showing edits"; "tables comparing existing thing with what you plan to do — this is how you will
  converse with me on technical matters")
- **Answer the scoped question and stop; PR/version mechanics are invisible to him.** (entry 44)
- **Caveats, when worth surfacing, = the most recent FEATURE-LEVEL edit/correction as ONE plain
  sentence about the feature** — never a technical-internals dump. (entry 44)
- **Questions the manager puts to the operator are held to the same bar.** (entry 97: "your
  question isn't worded to my standards" → table + literal edit + plain English)

## 2. What NOW COUNTS AS A VIOLATION (concrete, enforceable)
Any operator-facing reply OR question that does ANY of:
- **(a) Unglossed jargon.** Contains a token from the banned CLASS without its plain-English
  meaning substituted IN the sentence. Non-exhaustive list (the CLASS is what's banned, not just
  these strings): "scope expansion", "basis-mismatch", "denom", "raw", "coordinate",
  "registration", "Object L", "strong/tilt reading", "anchoring" (when NOT the project's own w=½
  anchor-curve sense — see entry-87 collision), "kernel-in-SCORE / kernel-in-WEIGHT", md5 /
  commit-hash / branch name, file path, agent ID, gate/harness name. If such a token is
  load-bearing it must be REPLACED by its meaning, not appended as a gloss.
- **(b) Technical but format-bare.** Technical content with NO existing-vs-proposed comparison
  table, OR NO core formula where one exists, OR an edit described but not shown literally.
- **(c) PR/version mechanics surfaced unasked.** Commit hashes, branch bookkeeping, "want me to
  open a PR?", md5s, version-control narration on his channel.
- **(d) Not answerable without scrollback.** Understanding the reply requires the operator to
  recall prior internal vocabulary or hunt context.

## 3. HOW I enforce (the ruling — confirms entry-44 mechanism, refined)
**POST-HOC transcript audit, NOT pre-clearance.** I do not review each reply before send — that
re-inserts the hub the operator deliberately removed and turns me into a bottleneck. Every
operator-facing turn is committed VERBATIM to `history/operator/<date>_<slug>.md` per CLAUDE.md
§2.2; that file is my audit surface. On summons or on my own pattern sweeps I raise:

> **FLAG-PROCESS (style-class) against the MANAGER**, against the artifact = the verbatim
> operator transcript turn, citing the offending text + which of (a)–(d) it trips.

A standing style FLAG-PROCESS is **halt-class** like every flag of mine (CLAUDE.md §2.1): the
manager may answer or correct it; the manager may NOT soften, shelve, or out-wait it; resolution =
the manager fixes the pattern or the operator overrules. This is **TYPE** policing — my content
authority (FLAG-WRONG / FLAG-OVERSELL / FLAG-OMISSION on claims) is unchanged and still outranks
the manager.
